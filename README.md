# STARA 데이터 수집 스크립트 — README

## 프로젝트 배경

STARA는 지역별 K-콘텐츠(아티스트) 관광 코스를 제공하는 여행 플랫폼이다.
서비스의 핵심 데이터는 **"지역 – 아티스트 – 장소(좌표)"** 조합인데,
네이버/카카오 개발자센터가 연령 제한으로 API 접근을 막아서
**공식 API 없이 네이버 블로그 게시물을 스크래핑 + 파싱**해서 데이터를 뽑는 방식으로 진행 중이다.

지금 이 데이터 품질이 엉망이라 정리가 필요한 상황.

## 현재 스크립트 동작 방식

- 입력: 네이버 블로그 URL (모바일 URL로 변환해서 iframe 구조 우회)
- 처리: `kiwipiepy`로 형태소 분석 → 정규식 패턴 매칭으로 후보 단어 추출
- 분류 카테고리 5종:
  - `아티스트`
  - `아티스트(추정-영문약어)`
  - `장소`
  - `주소`
  - `미분류`
- `ARTIST_LIST`라는 설정용 집합(set)이 스크립트 상단에 있어서, 비개발자 팀원도 아티스트 목록을 직접 추가/수정 가능
- 출력: long-format CSV (한 행 = 추출된 아이템 1개). 원래 wide-format(URL당 pipe로 구분된 여러 값)이었는데 후처리하기 어려워서 구조 변경함
- 파일명에 타임스탬프 포함, Excel에서 파일이 열려있어 저장 실패하는 경우를 대비해 데스크탑 경로로 fallback 저장

## 지금까지 잡은 버그 (참고용, 재발 방지)

1. **빈 집합 리터럴 vs dict 혼동** — `{}`는 dict라서 set 초기화에 `set()` 명시 필요했음
2. **한글 조사 결합으로 영어 단어 경계 깨짐** — 예: `"BTS와"`처럼 조사가 붙으면 정규식이 `BTS`를 못 잡던 문제
3. **순수 숫자가 영문 약어 패턴에 잘못 매칭** — 숫자만 있는 문자열이 "아티스트(추정-영문약어)"로 오분류되던 문제

## 지금 데이터가 왜 엉망인가 (파악 필요한 것들)

아래는 흔한 원인 후보들이다. Claude Code가 실제 CSV/스크립트를 열어서 다음을 확인해줬으면 함:

- [ ] `미분류` 비율이 너무 높지 않은지 (패턴이 너무 좁게 잡혀있을 가능성)
- [ ] 같은 장소/아티스트가 표기 차이(띄어쓰기, 영문/한글 혼용, 오탈자)로 중복 행 처리되고 있는지
- [ ] `장소`로 분류된 값 중 실제로는 음식점 메뉴명, 일반 명사 등 노이즈가 섞여있는지
- [ ] `아티스트(추정-영문약어)`로 분류된 것 중 진짜 아티스트가 아닌 오탐(false positive)이 얼마나 되는지
- [ ] 좌표/주소가 비어있거나 부정확한 행이 몇 %나 되는지
- [ ] 블로그 출처(URL)별로 품질 편차가 큰지 (특정 블로그 유형에서 파싱이 잘 안 되는 경우)

## 이번 작업 목표

1. 현재 스크립트와 CSV 출력물을 같이 검토해서 오분류/노이즈 패턴을 찾는다
2. 규칙 기반 필터링 또는 후처리 로직을 추가해서 정확도를 올린다
3. 사람이 최종 검수하기 쉽게 정리된 형태(예: 신뢰도 높은 것 / 검토 필요한 것 구분)로 재출력한다
4. 가능하면 재사용 가능한 형태로 정리 — 팀장(비개발자에 가까운 팀원)도 `ARTIST_LIST` 같은 설정값은 직접 관리할 수 있어야 함

## 참고

- 좌표 오류 하나가 퀘스트 인증(GPS 채점) 전체를 깨뜨리는 구조라, 정확도가 최우선 순위임
- 마감이 촉박하므로(9/20 웹사이트 링크 제출) 완벽한 정제보다는 "신뢰도별로 분류해서 사람이 빠르게 검수할 수 있게" 하는 실용적 접근이 우선
